    How to connect with WireGuard

    This guide walks you through creating a WireGuard profile and establishing a connection.

    Prerequisites

    • VPNConnect installed and daemon running (see How to install VPNConnect)
    • Access to a WireGuard VPN peer (server)
    • Either a wg-quick .conf file or the necessary parameters (peer public key, endpoint, allowed IPs, interface address)

    Option 1: Import a configuration file

    If you have a standard WireGuard wg-quick .conf file from your server:

    vpnconnect profile add \
  --protocol wireguard \
  --name myvpn \
  --wg-config /path/to/client.conf

    VPNConnect will: 1. Parse the .conf file 2. Extract the interface address, DNS, peer public key, and endpoint 3. Generate a new private key (if not in the .conf) 4. Display the public key for you to share with your server (if generated) 5. Store both keys securely in the keychain

    Example output:

    ✓ WireGuard profile 'myvpn' created successfully
  Public key: WqdMAwyPjpVL70y9Nqos4qQWtSdmhY7tE2crjninYUc=
  A new keypair was generated. Give the public key above to your WireGuard server administrator.

    Option 2: Configure manually

    If you don't have a .conf file, configure each parameter individually:

    vpnconnect profile add \
  --protocol wireguard \
  --name myvpn \
  --wg-peer-public-key "WqdMAwyPjpVL70y9Nqos4qQWtSdmhY7tE2crjninYUc=" \
  --wg-endpoint "vpn.example.com:51820" \
  --wg-allowed-ips "0.0.0.0/0,::/0" \
  --wg-address "10.0.0.2/32" \
  --wg-dns "1.1.1.1,1.0.0.1" \
  --wg-keepalive 25

    If you don't specify a private key with --wg-private-key, VPNConnect generates one automatically.

    Using an existing private key

    If you already have a private key and want to import it:

    vpnconnect profile add \
  --protocol wireguard \
  --name myvpn \
  --wg-config /path/to/client.conf \
  --wg-private-key "UGdBBm19cepidfbpCwUebu2Dd3RZJlWg8Ekz61Ll6Vo="

    The --wg-private-key flag overrides any private key in the .conf file.

    Adding a preshared key (optional)

    If your peer requires a preshared key for additional symmetric encryption:

    vpnconnect profile add \
  --protocol wireguard \
  --name myvpn \
  --wg-config /path/to/client.conf \
  --wg-preshared-key "optional-preshared-key-base64"

    Generating a new keypair

    If you need to generate a standalone keypair without creating a profile:

    vpnconnect profile wg-genkey

    Output:

    PrivateKey = UGdBBm19cepidfbpCwUebu2Dd3RZJlWg8Ekz61Ll6Vo=
PublicKey  = WqdMAwyPjpVL70y9Nqos4qQWtSdmhY7tE2crjninYUc=

    Give the public key to your server administrator.

    Using the graphical UI

    1. Open VPNConnect
    2. Click "Add Profile"
    3. Select "WireGuard" from the Protocol dropdown
    4. Either:
    5. Click "Import from wg-quick .conf" and paste your config file, or
    6. Fill in the fields manually (peer public key, endpoint, allowed IPs, interface address)
    7. If importing, the private/preshared keys are auto-populated; you can override them
    8. If configuring manually, click "Generate keypair" to create a new private key
    9. The public key is displayed for you to share with your administrator
    10. Click "Save Profile"

    Connecting

    vpnconnect connect --profile myvpn

    Check the connection status:

    vpnconnect status

    You should see output like:

    Connected: Yes
Profile: myvpn
Interface: wg0 (or utun123 on macOS)
Local IP: 10.0.0.2
Remote IP: <peer-endpoint-IP>
Connected at: 2026-09-12T08:15:00Z

    Viewing statistics

    Once connected, check traffic counters:

    vpnconnect statistics

    Output:

    TX Bytes: 1234567
RX Bytes: 9876543

    Disconnecting

    vpnconnect disconnect

    Troubleshooting

    "Invalid endpoint" error

    Symptom: wireguard: resolve endpoint: invalid endpoint

    Cause: The endpoint format is incorrect.

    Solution: Ensure it's in host:port format, e.g. vpn.example.com:51820 or 203.0.113.1:51820.

    "IPC error -22"

    Symptom: wireguard: apply config: IPC error -22: failed to set endpoint

    Cause: The endpoint hostname could not be resolved to an IP address, or the resolution result was not a valid IP.

    Solution: - Verify the hostname is correct and resolvable: nslookup vpn.example.com - Use a literal IP address instead if DNS is unreliable - Check that your system has network connectivity

    "Private key is not valid"

    Symptom: invalid private key

    Cause: The private key is not valid base64 or is malformed.

    Solution: Ensure the key is a valid 32-byte key encoded in RFC 4648 base64 (44 characters, including padding).

    Profile shows but doesn't connect

    Symptom: Profile appears in vpnconnect profile list but connect hangs or fails.

    Cause: Often a missing or incorrect peer public key, endpoint, or allowed IPs.

    Solution: 1. Check the profile: vpnconnect profile list 2. Review the configuration and ensure all required fields are present 3. Delete and recreate the profile if needed: vpnconnect profile remove --name myvpn
