    WireGuard support

    VPNConnect includes a full userspace WireGuard implementation using golang.zx2c4.com/wireguard. This document explains how WireGuard profiles work and how secrets are handled.

    Overview

    WireGuard is a lightweight VPN protocol with a small code surface and modern cryptography. Unlike Pulse Secure, which requires authentication and negotiation, WireGuard is simpler: you configure a private key and peer endpoint, and the tunnel immediately starts exchanging packets.

    VPNConnect's WireGuard connector: - Runs entirely in userspace (no kernel module required) - Operates on all three platforms (Linux, macOS, Windows) - Stores secrets (private and preshared keys) in the OS keychain - Supports configuration import from standard wg-quick .conf files - Allows on-the-fly key generation and display of the public key

    Profile structure

    A WireGuard profile stores these fields in the profile JSON:

    Field Storage Required Example
    wg_peer_public_key JSON Yes WqdMAwyPjpVL70y9...
    wg_endpoint JSON Yes vpn.example.com:51820
    wg_allowed_ips JSON Yes ["0.0.0.0/0", "::/0"]
    wg_address JSON Yes 10.0.0.2/32
    wg_keepalive JSON No 25
    dns JSON No ["1.1.1.1", "1.0.0.1"]
    mtu JSON No 1420
    Private key Keychain Yes (never in JSON)
    Preshared key Keychain No (never in JSON)

    The profile JSON itself never contains the private or preshared keys — these are retrieved from the OS keychain at connection time, ensuring they are never written to disk in plaintext.

    Secret key handling

    Private key

    Every WireGuard interface requires a private key (curve25519). The private key is:

    1. Generated or imported when the profile is created (via CLI or UI)
    2. Stored in the OS keychain under the key profile:<name>:wg_private_key
    3. Retrieved at connection time from the keychain and passed to the connector
    4. Never serialized to the profile JSON or logs

    The corresponding public key is computed from the private key and shown in the UI/CLI so you can share it with the server administrator.

    Preshared key (optional)

    If your WireGuard peer requires a preshared key (PSK) for additional symmetric encryption, you can optionally provide one. It is stored and handled identically to the private key:

    1. Stored in keychain as profile:<name>:wg_preshared_key
    2. Retrieved at connection time
    3. Never written to JSON

    Configuration import (wg-quick .conf)

    VPNConnect can import standard WireGuard configuration files in the wg-quick format:

    [Interface]
Address = 10.0.0.2/32
DNS = 1.1.1.1
MTU = 1420
PrivateKey = UGdBBm19cepidfbpCwUebu2Dd3RZJlWg8Ekz61Ll6Vo=

[Peer]
PublicKey = WqdMAwyPjpVL70y9Nqos4qQWtSdmhY7tE2crjninYUc=
Endpoint = vpn.example.com:51820
AllowedIPs = 0.0.0.0/0, ::/0
PersistentKeepalive = 25

    When you import a .conf file: - The [Interface] section's PrivateKey, Address, DNS, and MTU are extracted - The [Peer] section's PublicKey, Endpoint, AllowedIPs, and PersistentKeepalive are extracted - Profile fields are pre-populated; you can override them with CLI flags - The private and preshared keys are stored in the keychain after the profile is created

    Endpoint resolution

    When you specify an endpoint like vpn.example.com:51820, VPNConnect:

    1. Resolves the hostname to an IP address at connection time
    2. Pins that IP via the default gateway with a /32 route, ensuring tunnel traffic to the server doesn't loop back through the tunnel
    3. Passes the resolved IP:port to the WireGuard kernel module (wireguard-go requires a literal IP, not a DNS name)

    If your endpoint DNS changes mid-session, the tunnel continues using the old IP until you reconnect.

    Allowed IPs and split tunneling

    The wg_allowed_ips field specifies which traffic enters the tunnel. Common configurations:

    Use case AllowedIPs
    Full tunnel (all traffic) ["0.0.0.0/0", "::/0"]
    Only internal network ["10.0.0.0/8", "192.168.0.0/16"]
    Exclude ranges ["0.0.0.0/1", "128.0.0.0/1"] (split route to preserve endpoint pin)

    VPNConnect automatically splits 0.0.0.0/0 into two /1 routes when applying them, preserving the endpoint's physical /32 route.

    Key generation

    Via the CLI:

    # Generate a new keypair and display the public key
vpnconnect profile wg-genkey

    Via the UI:

    • When creating a WireGuard profile, click "Generate keypair" to create a new pair
    • The private key is generated and stored in the keychain immediately
    • The public key is displayed for you to share with your server

    Multi-platform support

    WireGuard implementation is identical across all three platforms:

    Platform TUN Implementation Default interface name Status
    Linux tun.CreateTUN from wireguard-go wg0 ✓ Tested
    macOS tun.CreateTUN from wireguard-go utun + auto-numbered ✓ Tested
    Windows Wintun driver via wireguard-go N/A (driver-managed) ✓ Supported

    All three platforms use the same userspace connector code with platform-specific TUN drivers selected at runtime.
